# ICCS102 — Term Project

**Build a Python Program You Can Explain**

**Total: 100 points — 60 team points + 40 individual points**  
**Teams:** Your assigned project groups, approximately six students per group.  
**Dates:** Checkpoint, submission and presentation dates will be announced in Google Classroom.

## 1. Your Task

Create a small, complete Python program that people can use or play. Choose a game, simulation or useful tool that interests your team.

Your program must have **three main features that work together**. A feature should perform a meaningful task, such as processing an order, updating a pet's needs or calculating a spending summary.

You will submit your code, demonstrate the program and answer individual questions about how the code works.

## 2. Program Requirements

Your program must meet these requirements:

| Requirement | What to include |
|---|---|
| Python program | A working Python program launched from `main.py`. |
| Conditions | Use `if`, `elif` or `else` for meaningful decisions. |
| Repetition | Use at least one `for` or `while` loop for a meaningful repeated task. |
| Functions | Divide the program into functions with clear purposes. Include parameter type hints and return type annotations; use `-> None` when a function does not return a value. |
| Collections | Use at least one collection type appropriately: **list, dictionary, set or tuple**. |
| Inputs and results | Accept supplied values or user actions and produce understandable results. Explain how to start, use and exit the program. |
| Input handling | Handle common invalid inputs or actions relevant to your interface without crashing. Preventing an invalid action through the interface is also acceptable. |
| Readability | Use clear names and useful comments where the logic needs explanation. |

Your team must write at least **200 meaningful lines of Python code in total across all source files**. Blank lines, comments, large blocks of fixed text or data, and copied or generated code do not count toward this minimum. Do not add unnecessary repetition or split statements across lines just to increase the count.

Use additional concepts, such as classes, nested loops or two-dimensional lists, where they suit your program.

You may supply values when running the program or calling its functions, use typed prompts, or build a graphical interface with buttons, keyboard controls or other actions. Multiple prompts or actions may form one complete interaction.

**Graphical interfaces and games are encouraged when they suit your idea and your team can manage them. A console program can also earn full marks.** Choose a scope you can finish, check and explain.

Python's standard library may be used. Obtain instructor approval before using external packages. Keep setup simple and include all files needed to run the program.

## 6. Presentation and Individual Questions

Follow the presentation schedule announced in class.

### Team demonstration — approximately 5 minutes

- Briefly explain the program's purpose and its three main features.
- Run the submitted program and demonstrate all three features.
- Show how the program handles or prevents an invalid input or action, or demonstrate an unusual situation relevant to your program.
- Identify any known limitation honestly.

Present using the running program and source code. Assessment focuses on functionality and your understanding of the code.

### Individual code questions

After the demonstration, each student answers questions selected by the instructor about the submitted code. Questions may ask you to:

1. Explain a function or section you helped implement.
2. Trace an input, predict the effect of a change, or explain how a small change to the logic could be made.

You may refer to the submitted source code. Answer independently, without teammates, AI or other assistance. You may ask for a question to be clarified. Marks are based on your understanding of the code.

Explain the logic in your own words and support your answer with reasoning or a step-by-step example. The instructor may rephrase a question or ask follow-up questions to clarify your understanding.

Every member must attend and participate independently. If you cannot attend for an approved reason, arrange a separate individual check with the instructor.

## 7. AI Use and Academic Integrity

**Your team must write its own project code and submission text.** You may use class materials and documentation, discuss the work within your team, and ask the instructor or TA for guidance.

| Permitted learning support | Not permitted |
|---|---|
| Asking AI to explain a general Python concept or the meaning of an error message | Asking AI to generate, complete, fix or rewrite your project code, including through AI coding assistants |
| Studying small examples unrelated to your project, then developing your own solution | Copying, adapting or retyping AI-generated solutions for your project |
| Consulting documentation and acknowledging resources used | Copying or adapting another team's code or a ready-made project, including previous students' work |
| Recording the tools and topics used for learning | Using AI to draft or rewrite the team report, program-check explanations, contribution statements or presentation script |

For example, asking “How does a dictionary work?” is permitted. Asking “Write the stock-management function for our café project” is not.

Do not share project code with other teams or have anyone outside your team write it. All contribution statements and reported results must be truthful. Listing a source or AI tool does not make prohibited use acceptable.

Plagiarism, prohibited AI-generated work and false claims of contribution may result in **zero for the term project** and referral under the university's academic integrity procedures. Further penalties, including **failure of the course**, may apply under those procedures.

Minor wording mistakes or slips you correct yourself do not automatically reduce your marks.
